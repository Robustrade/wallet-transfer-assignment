# API

Base URL for local runs: `http://localhost:8080`

JSON field names match the assignment. Amounts are JSON integers in minor currency units, never strings or fractional numbers.

## Errors

Client errors use one envelope:

```json
{
  "error": {
    "code": "VALIDATION_ERROR",
    "message": "request validation failed",
    "details": [
      {"field": "amount", "message": "must be greater than 0"}
    ]
  }
}
```

`details` is omitted when there is no field list. Internal failures return `500` with code `INTERNAL_ERROR` and a fixed message. Database errors are logged server-side and are not copied into the response.

| HTTP | Code | When |
| --- | --- | --- |
| 400 | `VALIDATION_ERROR` | Malformed JSON, unknown fields, invalid ids, non-integer amount, same wallet, amount out of range |
| 404 | `WALLET_NOT_FOUND` | Wallet id is well formed and missing |
| 404 | `TRANSFER_NOT_FOUND` | Transfer id is missing |
| 409 | `WALLET_EXISTS` | Wallet id already exists |
| 409 | `IDEMPOTENCY_KEY_REUSED` | Same key, different from/to/amount |
| 415 | `UNSUPPORTED_MEDIA_TYPE` | Body is not JSON |
| 422 | `AMOUNT_OVERFLOW` | Credit would overflow a signed 64-bit balance |
| 503 | `RESOURCE_BUSY` | Lock or statement timeout; the client may retry with the same key |
| 500 | `INTERNAL_ERROR` | Unexpected failure |

A transfer that is recorded as `FAILED` because of insufficient funds is not this envelope. It is the transfer resource, with HTTP 422. See below.

## POST /wallets

Creates a wallet. `initialBalance` is optional and defaults to `0`. It is administrative opening funding, not a ledger transfer.

```json
{ "id": "wallet_1", "initialBalance": 1000 }
```

`201 Created`

```json
{
  "id": "wallet_1",
  "balance": 1000,
  "initialBalance": 1000,
  "createdAt": "2026-10-01T12:00:00Z",
  "updatedAt": "2026-10-01T12:00:00Z"
}
```

## GET /wallets/{walletId}

`200 OK` with the same wallet object.

## POST /transfers

```json
{
  "idempotencyKey": "abc123",
  "fromWalletId": "wallet_1",
  "toWalletId": "wallet_2",
  "amount": 100
}
```

`idempotencyKey` is required. The key, both wallet ids, and the amount are the idempotency fingerprint. A retry with the same fingerprint returns the original transfer id, status, and timestamps. A retry with the same key and a different fingerprint returns `409` and does not create another transfer.

`201 Created` when the transfer is `PROCESSED`:

```json
{
  "id": "6f1c1d3e-1b2a-4c5d-8e9f-001122334455",
  "idempotencyKey": "abc123",
  "fromWalletId": "wallet_1",
  "toWalletId": "wallet_2",
  "amount": 100,
  "status": "PROCESSED",
  "createdAt": "2026-10-01T12:00:00Z",
  "updatedAt": "2026-10-01T12:00:01Z"
}
```

`422 Unprocessable Entity` when the transfer is stored as `FAILED`:

```json
{
  "id": "6f1c1d3e-1b2a-4c5d-8e9f-001122334455",
  "idempotencyKey": "abc123",
  "fromWalletId": "wallet_1",
  "toWalletId": "wallet_2",
  "amount": 100,
  "status": "FAILED",
  "failureReason": "INSUFFICIENT_FUNDS",
  "createdAt": "2026-10-01T12:00:00Z",
  "updatedAt": "2026-10-01T12:00:01Z"
}
```

The replay of either outcome uses the same status code and body. Money moves only on the first successful `PROCESSED` commit.

If a wallet does not exist, the transaction rolls back, the key is not consumed, and the response is `404`.

## GET /transfers/{transferId}

`200 OK` with the transfer object.

## GET /transfers/{transferId}/ledger

`200 OK`

```json
{
  "transferId": "6f1c1d3e-1b2a-4c5d-8e9f-001122334455",
  "entries": [
    {
      "id": "…",
      "walletId": "wallet_1",
      "transferId": "6f1c1d3e-1b2a-4c5d-8e9f-001122334455",
      "type": "DEBIT",
      "amount": 100,
      "createdAt": "2026-10-01T12:00:01Z"
    },
    {
      "id": "…",
      "walletId": "wallet_2",
      "transferId": "6f1c1d3e-1b2a-4c5d-8e9f-001122334455",
      "type": "CREDIT",
      "amount": 100,
      "createdAt": "2026-10-01T12:00:01Z"
    }
  ]
}
```

A failed transfer returns an empty `entries` array. A missing transfer returns `404`.

## GET /health

`200 OK` when the database answers a ping.

```json
{"status": "ok"}
```

`503` with code `UNAVAILABLE` when it does not.

## Identifiers

Wallet ids and idempotency keys use ASCII letters, digits, `_`, and `-`. Wallet ids are 1–64 characters. Idempotency keys are 1–128 characters. Transfer ids are UUID strings generated by the service.

## Example

```bash
curl -s -X POST localhost:8080/wallets -H 'content-type: application/json' \
  -d '{"id":"wallet_1","initialBalance":500}'

curl -s -X POST localhost:8080/wallets -H 'content-type: application/json' \
  -d '{"id":"wallet_2","initialBalance":0}'

curl -s -X POST localhost:8080/transfers -H 'content-type: application/json' \
  -d '{"idempotencyKey":"abc123","fromWalletId":"wallet_1","toWalletId":"wallet_2","amount":100}'
```
